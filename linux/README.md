# Linux

MoQCast 的通用 Linux 桌面端实现放在此目录。

## 共享来源

X11 会话在共享页列出显示器，支持手动刷新；启动前重新枚举确认来源，来源失效或显示器布局变化时要求刷新并重新选择，不静默改采其他屏幕。共享期间来源和系统声音设置锁定，停止后才能重选。显示器选择、布局变化与重复共享仍需真实 X11 桌面验证。

本批暂不开放 X11 窗口选择：现有接口仅传窗口编号，枚举和实际打开之间存在窗口销毁后编号被复用的身份竞态。后续需先确定底层选源身份与生命周期保证，不能仅靠重复枚举宣称已解决。

Wayland 会话提供“屏幕／窗口”切换，点击共享后由系统 Portal 选择具体来源，不枚举原生 Wayland 窗口，也不将 XWayland 列表冒充该列表。停止后再次共享会重新弹出选择器；同一次共享因观看需求自动重开时，在 Portal 支持授权恢复的情况下复用原选择。共享期间不能切换来源。

固定的上游 `moq-video` 基线已包含按来源类型请求与每次共享独立的授权恢复。环境不支持所选类型，或 Portal 未返回恰好一个、类型匹配的来源时明确报错，不将窗口请求改成整屏。ScreenCast v1/v2 可省略来源类型；v3 及以上必须返回，显式类型不匹配始终拒绝。接口已由上游 PR #5089 接纳；本地仍保留等待 Portal 关闭确认等产品补丁。

之前的 Ubuntu 24.04.3 LTS 真机测试已确认屏幕/窗口内容、静止画面、缩放、关闭窗口结束共享及取消后换屏正常。新的依赖基线、其他合成器及观看者离开后重新加入仍待验证。最小化行为由合成器决定，不能沿用 Windows WGC 验收结论。系统声音仍是设备系统输出，不代表选中窗口独占的音频。X11 的 MIT-SHM 是该后端内部的优化，缺少支持时沿用 GetImage，与 Wayland/Portal 并列而非替代。

## Linux capture parity 的应用范围

| 能力 | 本应用行为 |
| --- | --- |
| Wayland 屏幕 / 单窗口 | 系统 Portal 选源；检查来源数量、明确类型与 Portal 版本能力 |
| 授权恢复与重选 | 同次共享按需恢复；停止后 Start 新建选择 |
| 系统声音 | 已有 PipeWire 输出 monitor → Opus，与视频 Portal 独立；可配合屏幕或窗口共享 |
| 整应用全部窗口 | 明确不支持；不枚举或自动加入同一应用的其他、新建窗口 |
| X11 | 保留显示器选择，应用窗口入口仍暂缓 |

这里复用 Desktop 自己的 `linux/src/publish/audio.rs`，不需要先向 moq-dev 投稿，也没有将系统声音伪装为上游 `moq_audio::capture::Source::System` 的 Linux 实现。系统声音默认关闭，只在本次发布选中时启动；发布与观看共用一个媒体状态，不能同时占用。该互斥是应用行为，不代表音频后端具备上游所要求的通用“排除本进程”能力。

这批只对齐 quest 在 Desktop 的功能范围，不关闭上游 quest。完整上游系统音频接口不在本批范围内，真实 Wayland 音画、停止重开与授权验证仍须以测试包验收。

## Nearby 多地址连接

普通 LAN 设备的同一份广告地址作为一个连接目标，复用上游 QUIC 交错拨号；某个地址不响应时，后续候选不必等待它超时。地址保留 IPv6 scope，沿用证书指纹与凭据校验、原有连接预算和取消机制。只有握手赢家进入业务会话；显式 node URL 保持原有处理。单独的 mDNS Lost 仍不会拆除健康连接。

三端消费者锁文件使用 `mdns-sd 0.21.4`，包括冲突改名后的 goodbye 修复。这不能代替跨重启身份管理，也不保证所有网络环境都能连接。

## UI v2 开发候选

UI v2 候选复用 shared-ui 的主题、内嵌字体、品牌、页头、设备行、弹层与播放器。观看从附近设备进入，返回列表不停止播放；共享位于本机上下文，开始/停止区不随来源列表滚动。设置提供跟随系统/浅色/深色、语言与常规日志导出。Portal 屏幕/窗口和 X11 选屏能力保持各自边界。

本次主机侧 UI 回归不代表 Linux 原生布局或媒体验收；Wayland/X11、窗口管理器、高 DPI 和保存日志对话框需用目标构建验证。

## Nearby 状态与操作权限

设备发现、精确关联连接和可观看内容由[共享状态策略](../shared/lan-state/README.md)组合显示。单独 mDNS Lost 不会隐藏有效连接或广播；观看根据有效路由准入，不用无关设备的全局入站数量判断。本机 LAN 就绪后可开始共享并等待观看者，发布与观看仍互斥。关闭过程中禁止新的共享和观看。

匿名入站会话目前不能可靠映射到某个 mDNS 设备，不能据此宣称该设备已连接。当前关闭仅有应用 owner 的可观察清理；上游 mDNS Drop 仍是 best-effort 请求，不是 daemon/socket 全部释放的证明。

关闭 LAN 时会等待出站连接循环和本应用拥有的清理任务退出；主动取消与任务异常分别处理。一个任务清理失败不会跳过其余资源，详细错误记录到日志，界面保留关闭异常。mDNS 的底层 daemon 退出仍不可等待，不能把应用任务结束等同于远端立即离线。

固定依赖仍有 mDNS 创建完成前取消的清理缺口；启动中关闭涉及这一路径。现有应用任务退出不构成底层 daemon 已退出的证明，此边界仍需上游修复接入后验证。

## LAN 地址刷新与诊断

同一设备的拨号尚未完成时，发现新增地址会更新候选连接，沿用本轮原有截止时间；重复地址不重新计时，已建立的连接不因补充地址而被替换。凭据变化继续按身份替换处理，旧代次的结果不能覆盖新连接。

联调前在设置中开启详细诊断，再开启附近设备。日志保留设备 ID、发现地址、刷新前后地址、连接代次、剩余预算、逐地址失败原文、握手阶段和连接关闭原因；正常模式不放开底层 DEBUG。入站编号只表示本机接纳的会话，不推断它属于某个 mDNS 设备。导出三端日志并提供操作时间，可对齐事件顺序；日志不能替代抓包或保证复现当时的网络环境。
