## ADDED Requirements

### Requirement: A · 区分请求、实际后端与执行方式

应用 SHALL 在发布端「共享信息」和观看端「播放信息」展示本端角色、codec、已知尺寸及策略；实际后端与软硬件执行方式须分别有本次运行证据。等待首个有效样本时显示「等待中」，本构建取不到的字段显示「未提供」。

#### Scenario: 自动编码选中软件实现

- **WHEN** 本次请求 H.264 自动编码，运行时确认选中了 OpenH264
- **THEN** 共享信息和导出均给出「自动」「H.264」「OpenH264」「软件编码」
- **AND** 仅在后端报告了失败尝试时记录回退和原因，否则只报告最终选择

#### Scenario: 软解帧经过 GPU 呈现

- **WHEN** 解码器输出软件解码帧，由 GPU 转换或绘制
- **THEN** 解码栏显示实际软件解码器，呈现路径单列；两端只报告本端能够观测的事实

#### Scenario: 重建和迟到回调

- **WHEN** 同次会话重建编解码器，或上一次观看的时间较晚的回调到达
- **THEN** 记录本次重建并在确认后更新后端；旧会话回调不能改变当前会话的界面、计数或摘要

#### Scenario: SDK 跨线程报告解码回退

- **WHEN** SDK 的工作线程报告硬件候选被拒，但没有当前解码实例的会话身份
- **THEN** 仍可展示返回的解码器实例名；界面和摘要不为该会话填写回退原因

### Requirement: A · 下一次观看使用选定的解码策略

应用 SHALL 提供默认「自动」和受支持的「仅软件」解码选项。界面说明生效时点，运行中修改只影响下一次新观看；按设计稿建议，偏好限本进程。

#### Scenario: 同源两次观看

- **WHEN** 自动观看时选择「仅软件」，停止后重新观看同一发布源
- **THEN** 第一轮继续原路径；第二轮以新的会话标识应用严格策略，显示运行时选中的后端或启动失败原因
- **AND** 恢复自动在下一次观看生效，退出应用后恢复默认

### Requirement: A · 本地导出会话摘要

应用 SHALL 在用户主动导出的诊断 ZIP 中包含带格式版本的会话摘要，支持当前会话及最近一次已结束会话。摘要应能独立确认构建、会话、角色、策略、实际后端、开始时间、观测范围与结束原因。

#### Scenario: 结束后导出并开始下一轮

- **WHEN** 停止第一轮并导出，再开始第二轮、使用同一构建导出
- **THEN** 两份摘要的会话标识可区分，运行中导出标记「进行中」，结束后导出标记真实终止原因；旧记录不被重新解释
- **AND** 用户能看到包含的资料类别；摘要不含媒体样本、窗口标题、完整端点、凭据或可长期追踪的设备标识

#### Scenario: 确认导出后立即重开会话

- **WHEN** 用户在第一轮观看时确认 ZIP 路径，随后停止并重开观看，后台写盘在第二轮才开始
- **THEN** ZIP 中的当前会话仍使用确认时的第一轮会话 ID、运行状态和实际解码器

#### Scenario: Windows 发布停止后立即重开

- **WHEN** 正常停止正在进行的共享并马上再次共享
- **THEN** 第一轮保留 `stopped`，第二轮使用独立标识，旧完成事件不能终止第二轮
- **AND** 非主动中断保留 `cancelled`，捕获错误保留 `failed`；已确定的结果不因迟来的停止请求而改变
